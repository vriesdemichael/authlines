Which spec says so?

In Keycloak: Client scopes

What the access token says about the user comes from the client's default client scopes, whether or not the app asked for openid. A new client has profile and email among them, so its token already holds a name and an email address. Take those two off and they are gone.

Clients › your client › Client scopes

Changed this, and the answer changed, on Keycloak 26.8.1.

In Keycloak: Access Token Lifespan

Sets expires_in for this client. Left empty, it comes from the realm, which is five minutes on a new one.

Clients › your client › Advanced › Advanced settings › Access Token Lifespan

Changed this, and the answer changed, on Keycloak 26.8.1.

In Keycloak: Audience mapper

A default client's access token names account as its audience, not your API, so an API that checks the audience refuses it. Here account comes from the default roles client scope, and without that scope there is no audience at all. Add an Audience mapper to the client's dedicated scope to name your API. The demo API here is told to accept account, so that it can run against a default client, which means any default client's token in this realm gets in. Yours should expect its own name.

What it carries

  • access_token body What the app shows an API to be let in.
  • token_type=Bearer body Says how to use the token: whether holding it is enough, or it takes a proof too.
  • id_token body Tells the app who logged in. From: OpenID Connect
  • expires_in body How many seconds the access token lasts.
  • scope body What the access covers, which is not always what was asked for.
