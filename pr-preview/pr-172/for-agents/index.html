Authlines

Links for an AI agent

Authlines draws OAuth and OpenID Connect flows as sequence diagrams, recorded from a real Keycloak 26.8.1. If you are an agent helping someone with their own system, you can link to the flow and settings that match it, open it on the step you are explaining, and put their names on the parties. They get a diagram to step through, with who has seen what, and the requests a real server sent.

Nothing here contacts their system. You describe it with a link, and the site draws its own recording with their names on it.

The address

https://vriesdemichael.github.io/authlines/<flow>/[setup/]?<settings and view>#v=1&<party>=<name>

Leave out a setting to keep its default. The flow, its settings and the step are in the query, so the link opens exactly that. A setting that does not fit with the others is turned off, and the screen says why.

Names for the parties

  • They go after #, start with v=1, and name parties by the ids listed for each flow: #v=1&app=Payroll&idp=Entra%20ID.
  • They change the names on the heads of the diagram and nothing else. Every request and answer shown stays the one recorded on the site’s own server, and the raw view says which recorded value is which named party.
  • A name is plain text of at most 32 characters. No < or >, no address, nothing that looks like a token, and nothing that does not show.
  • The part after # stays in the browser and never reaches a server. Anyone the link is shared with sees the names, so never put a secret in one.
  • A party the flow has, but that these settings do not draw, is simply not shown. A party the flow does not have, or a name that does not fit, is left out and said, beside the diagram.

Examples

  • A web app on a server, logging people in with OpenID Connect and PKCE, at a provider that is not Keycloak.
    https://vriesdemichael.github.io/authlines/authorization-code/?oidc=1&pkce=1&keycloak=off#v=1&app=Payroll&idp=Entra%20ID&api=HR%20API
  • The same app, where the identity provider sends the code back through the browser, in advanced mode.
    https://vriesdemichael.github.io/authlines/authorization-code/?mode=advanced&oidc=1&pkce=1&keycloak=off&step=redirect-with-code#v=1&app=Payroll&idp=Entra%20ID&api=HR%20API
  • How that app gets set up with its provider.
    https://vriesdemichael.github.io/authlines/authorization-code/setup/?oidc=1&pkce=1&keycloak=off#v=1&app=Payroll&idp=Entra%20ID&app-team=Payroll%20team&idp-admin=IT
  • A job with no user, calling an API with a token of its own.
    https://vriesdemichael.github.io/authlines/client-credentials/#v=1&app=Nightly%20export&api=Billing%20API
  • A television app where the person logs in on their phone.
    https://vriesdemichael.github.io/authlines/device/#v=1&app=Living%20room%20TV&browser=Their%20phone
  • A link with no version, which draws the site’s own names and says why.
    https://vriesdemichael.github.io/authlines/authorization-code/#app=Payroll

How it is shown

  • mode=advanced: Raw requests and answers, which spec says so, and server notes.
  • step=<id>: The step to open on. Each diagram lists its steps below.
  • say=specs: The specs’ names for the parties. say=keycloak for Keycloak’s.
  • keycloak=off: No notes about Keycloak. Use this when the person’s identity provider is something else, and give it its name with idp=. The traffic shown is still the site’s own Keycloak’s, and the raw view says so.
  • eyes=<party>: The whole flow as one party saw it, such as eyes=browser.
  • whole=1: Every step at once, for a room.

Authorization code flow: authorization-code

An app gets access on behalf of a user, without ever seeing their password.

Settings

  • oidc=1: OpenID Connect, off by default.
  • consent=1: Ask for consent, off by default.
  • client=confidential | public: Client type, confidential by default.
  • register=manual | dcr | cimd: How the provider learns about the app, manual by default.
  • pkce=1: PKCE, off by default.
  • par=1: PAR, off by default. Only drawn so far with OpenID Connect, consent, PKCE and either kind of client, on a server.
  • attacker=1: Show an attacker, off by default. The attacker only shows the plain case, with a Bearer token and no other provider.
  • thief=1: Show someone using a stolen token, off by default. Only with a DPoP token, in the plain case so far.
  • checks=proof | bearer: What the API checks, proof by default. Only someone using a stolen token asks this.
  • uses=themselves | real-app: What they do with it, themselves by default. Only an app with a secret needs this, and only for a copied code. With no secret, they can just trade it.
  • gets=copy | link: How they get the code, copy by default. Only in the plain case so far, with the app on a server.
  • registered=exact | any: What the app registered, exact by default. Only a link of theirs asks this.
  • binding=bearer | dpop: Token type, bearer by default.
  • nonce=1: Server requires a nonce, off by default. A DPoP nonce only applies to DPoP tokens.
  • broker=1: External IdP, off by default.
  • directory=1: Users in a directory, off by default. Only drawn in the plain case so far.
  • companies=1: Each customer has a provider, off by default. Only with another provider, in the plain case so far.
  • speaks=oidc | saml: What their provider speaks, oidc by default. Only a customer's own provider is asked this.
  • leaves=1: Someone leaves the company, off by default. Only someone at a customer with a provider of their own leaves it.
  • upstream=off | v1 | v2: Stored upstream tokens, off by default. Upstream tokens only exist when another IdP handles the login.
  • send=good | none | expired | changed | elsewhere | noscope: What the API is sent, good by default. This shows the plain case, so other settings do not get in the way of the answer.
  • refresh=1: When the token runs out, off by default. This shows the plain case, so other settings do not get in the way of the answer.
  • reuse=keeps | ends: Using a refresh token twice, keeps by default. There is no second use until the token runs out and the first has happened.
  • sso=1: Log in to a second app, off by default. This shows the plain case, so other settings do not get in the way of the answer.
  • second=remembered | insists | fresh: What happens at the second app, remembered by default. There is no second app until it has been brought on.
  • logout=1: Log out, off by default. It is part of OpenID Connect.
  • runs=server | page | bff: Where the app runs, server by default.
  • address=registered | other: The address the app asks for, registered by default. It stops before any of those would matter.
