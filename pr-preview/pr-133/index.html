Authlines

Flip one thing. Watch the login change.

OAuth and OpenID Connect on one diagram, recorded from a real server. Pick a question and follow it, one message at a time.

  1. Start here

    8 What everything else builds on, in plain words.
    1. How does an app get access? An app acts for a user, without ever seeing their password.
    2. Why not just send the token back through the browser? Why the browser only gets a code, and what happened to the way that did not.
    3. What can the browser see? The whole flow with everything the browser was not sent hidden.
    4. How does an app know who logged in? Access is not identity, which is what OpenID Connect adds. OAuth alone is not login.
    5. When does the user get asked? What a scope is, and why you may never have seen the question.
    6. What is single sign-on? Why don't I log in twice? A second app, the same login, and no password.
    7. How do an app and a provider get to know each other? What people have to do before anyone can log in.
    1. I have to add login to an app. What do I do? The part you do once, which part of your code is left, and what a library does. An app with no browser takes the device flow.

  2. When something goes wrong

    8 An error on your screen, and what it means.
    1. Why do I get Invalid parameter: redirect_uri? Where the address is checked, and where it was registered.
    2. Why did my API say 401? It does not accept the token, for one of several reasons that look the same.
    3. What is the difference between 401 and 403? One is about the token, and the other about what it allows.
    4. What does an API say to a call with no token? Which kind of token it wants, and no error.
    5. What if someone changes what a token says? Anyone can read one, and nobody else can sign it.
    6. Why does my API refuse a token that is still good? It has to be for this API, which takes setting up at the identity provider.
    1. Why do I get login_required? Someone would have to log in, and the server was told not to ask.
    2. Why do I get Maximum allowed refresh token reuse exceeded? A refresh token was used twice, and that ended things for this app.

  3. Keeping it safe

    16 What can go wrong, and what stops it.
    1. What does state protect against? Cross-site request forgery, or CSRF: someone slipping their own answer into your login.
    2. What is iss doing in the address? Advanced It says which server answered.
    1. What is different about an app with no secret? An app in a browser or on a phone cannot keep one, so what proves who it is?
    2. What if someone steals the code? Watch them take it as it crosses the browser, and get the tokens.
    3. How does PKCE work? The app proves it started this login, with a value that was never in a redirect.
    4. What does PKCE do to the attacker? The same attempt, a different answer, and a cost that remains.
    1. Can a code be stolen from an app with a secret? They get the code, but cannot trade it. That is not the end of it.
    2. Does an app with a secret need PKCE too? Why current advice recommends it, even when a stolen code is not enough alone.
    3. What does an attacker get against both? A secret and PKCE together, against the same attempt.
    1. What does PKCE add to the requests? Advanced A verifier, and a fingerprint of it.
    2. What stops them handing it to the real app? The code is tied to the login it came from.
    3. Does a nonce stop it as well? Advanced Yes, if the app checks it, and later.
    1. What is a stolen refresh token worth? More than the access token, and a new one coming back may not stop it.
    2. How do I make refresh tokens rotate? Advanced A new one coming back is not enough: the old one has to stop working.
    3. How does DPoP stop a stolen token being used? It ties a token to a key that stays in the app. The theft itself is not drawn.
    4. How can a proof be stopped from being used later? A nonce from the server. The spec allows it, and the server recorded here did not ask.

  4. Logging in somewhere else

    3 When the identity provider hands the login to another one.
    1. How do you log in with another provider? The app does not notice, and that is the point. It is one way "log in with your company account" works.
    2. How does the app call the other provider's API? Advanced The identity provider kept its tokens, and hands them over.
    3. What changes with API V2 for stored tokens? Advanced Only the access token, and the client has to be allowed to ask.

  5. Setting up a real app

    10 The combinations people use, with what is really sent.
    1. What does my API have to check? A token says nothing until someone has looked.
    2. What happens when the token runs out? The app gets a new one, and the user never knows.
    1. What does log out actually do? Two sessions end, if you ask for both, and an access token keeps working.
    2. I logged out. Does the token still work? The same token, and two answers.
    3. Am I logged out of my other apps too? They lose the session they relied on, and may not know yet.
    1. A web app on a server Advanced It can keep a secret. With OpenID Connect to know who logged in, and PKCE on top.
    2. An app that runs in the browser A single-page app, in React, say. No secret to keep, so PKCE protects the code. The tokens then live in the page, which is the harder problem.
    3. Where should an app in the browser keep its tokens? localStorage, sessionStorage or memory: none of them fully stops a script in the page. A backend for frontend keeps tokens out of it, though a script can still act through the open page.
    4. What if our client secret is in the JavaScript? Then it is not a secret, and anyone can read it.
    5. How do I make someone log in again? Advanced A session is usually good enough. One parameter says not this time.

  6. Under the hood

    4 What really happens, for when you want to see it.
    1. What really goes over the wire? Advanced The raw request and answer, from one real run.
    2. Do two apps share a token? Advanced They share a login, and each has tokens of its own.
    3. Why does my access token say that? Advanced Open it, and see which setting put each thing there.
    4. What does it all look like at once? Advanced As much as fits together, to see how far one diagram stretches.

  7. When there is no user

    3 Client credentials: one service calling another, with nobody logging in.
    1. What if no user is involved? A nightly job, or one service calling another: machine to machine, with no browser and no login.
    2. Why is there no refresh token for a service? It has its secret, so it can just ask again.
    3. Can a token for a service be tied to a key? Advanced DPoP works the same with no user.

  8. On a TV, or a server with no browser

    11 Device flow: when the app cannot log anyone in, and the user does that on another device.
    1. How do you log in on a TV, or on a server with no browser? On another device, with a code the app shows. That includes a command-line tool over SSH on a headless server.
    2. Why are there two codes? One for a person, and one that gets the tokens.
    3. What is the app doing while the user types? Asking, again and again, which is called polling.
    4. Can someone trick me into approving their device? Yes, by sending you their code. It is called device code phishing.
    5. What if someone else can see the user code on the screen? They can get there first, and the device ends up logged in as them.
    1. What if the user says no? Advanced The app is told the next time it asks, and stops.
    2. What if the user never comes? Advanced The codes run out, and the app is told when it next asks.
    3. What stops someone who sent me a code? Advanced You do, at the page that asks. Nothing else here can.
    4. What if I ignore a code someone sent me? Advanced It runs out, which is why these codes are short-lived.
    5. Why do I get authorization_pending? Advanced It is not a failure, whatever it looks like.
    6. Can a device know who logged in? Usually, with an ID token.

Recorded from Keycloak, a free identity provider you can run yourself. The specs are the same elsewhere, though the wording of errors, token formats and defaults are Keycloak's own. Open source: see the code, the recordings and how they are checked.
