Which spec says so?

In Keycloak: Valid redirect URIs

Checked when the request is pushed. An address that is not one of these gets a 400 at the push, which says: Invalid parameter: redirect_uri, so the app has no reference to send the user with. That holds for an app with no secret too.

Clients › your client › Settings › Access settings › Valid redirect URIs

Changed this, and the answer changed, on Keycloak 26.8.2.

In Keycloak: Pushed authorization request required

Off on a new client, so it takes an ordinary login link as well as a pushed one, and someone else can still start a login for it with a link of their own. On, a link that was not pushed sends the browser back to the app with error=invalid_request and: Pushed Authorization Request is only allowed. For an app with no secret that stops less, because anyone can push a request for it.

What it carries

  • response_type=code body Asks for a code, which is what makes this the code flow.
  • client_id body Says which app this is, as registered in setup.
  • redirect_uri body Checked now, before the user is sent anywhere
  • state body A random value the app checks when the user comes back, so nobody can slip an answer into this user's login. It does not stop someone starting a login in their own browser and handing the app a stolen code, which takes PKCE or a nonce.
  • code_challenge body Straight to the identity provider, and never through the browser From: PKCE
  • code_challenge_method=S256 body How the fingerprint was made: a one-way hash From: PKCE
